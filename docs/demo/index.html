Under the hood

The graphs are checked in.

The MCP server is the front door. The graph definitions and the code that enforces them live in the repository.

01

Assignment graph

One feature, bug, or investigation moves from request to completion. Failed checks can send it back to implementation.

.agent/graph.yaml
intake → classify → context
→ outcome → plan → implement
→ verify → review → deliver → complete
02

Batch graph

Several assignments can be planned together, then worked one at a time so dependencies and order stay visible.

.agent/graph.yaml
intake → plan → execute
→ next ticket → complete
